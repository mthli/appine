# Modules

Registry of module IDs used by `.agents/maps/`, `.agents/decisions/` and `MODULE:` Decision blocks.

## Structural modules

- `engine` — CPU engine core and Tier 0 interpreter: `core/engine/` except `kernel/mmu`'s page table and TLB fill/flush and `engine/dbt`'s Tier 1 translator (`interp.c`, `simd.c`, `atomic.c`, `native.c`, `cpu.c`, `features.c`, `guard.c`, `internal.h`, `build.rs`, `include/appine/engine.h` except its MMU and Tier 1 sections, `src/lib.rs` except its Page table and Tier 1 sections, `tests/interp.rs`, `tests/guard.rs`) plus `tests/lockstep`; Tier 0 execution and whitelist reference, native stubs, CPU state contract, CPU features and ID registers, host fault guard.
- `engine/dbt` — Tier 1 same-ISA dynamic binary translator: `core/engine/src/c/dbt.c`, `dbt_internal.h`, `dbt_translate.c`, `dbt_group.c`, `dbt_loop.c`, `dbt_routines.c`, `dbt_cache.c`, `emit.h`, the Tier 1 section of `include/appine/engine.h`, the `Tier 1` section of `src/lib.rs` (`DbtStats`, `DbtRegs`, `DbtMemop`, `MEMOP_*`, `DbtSource`, `DbtSpace`, `Dbt`, `trim_dbt_pool`, `unmap_written_code`, `written_code_bytes`), `core/engine/tests/dbt.rs`, and `core/engine/tests/dbt_loop.rs`; block translation, inline soft-TLB and grouped checks, block chaining and return prediction, dispatcher, length-gated libc memops, W^X code cache, lock-free table, templates, instance pool, code-group sharing and content-based invalidation.
- `kernel/process` — processes, threads and scheduling: `core/kernel/src/task.rs`, `process.rs`, `kernel.rs` (BKL, `Cx`, wake-ups; except the `INIT` constant in kernel/boot, `Shared::stop_checks`/`resume_checks` in kernel/time and `Hold`/`HoldSample`/`Entry`/`Doing`/`doing`/`done` in kernel/bug), `cell.rs`, `syscall/mod.rs` (the dispatcher, except its restart and unimplemented-syscall handling, kernel/time's time helpers and kernel/bug's `TEST_SYSCALL` arm), `syscall/proc.rs` (except its execve and unshare sections), `syscall/fast.rs` (except its futex call), `syscall/misc.rs` (except what kernel/signal, kernel/futex, kernel/ns, kernel/time and kernel/boot list there: resource use and limits and the remaining process-wide calls), `machine.rs` except kernel/boot's lifecycle types/functions, kernel/time's `timers` and kernel/bug's `take_kills`/`stall`, `syscall/sched.rs`; task lifecycle, syscall dispatch, BKL and the fast path, waiting, host process statistics and wait helpers.
- `kernel/time` — clocks, sleeps and timers: `core/kernel/src/itimer.rs`, `syscall/posix_timer.rs`, `loadavg.rs`, `machine.rs`'s `timers`, `Shared::stop_checks`/`resume_checks` in `kernel.rs`, `read_timespec`, `timespec` and `KTIME_MAX` in `syscall/mod.rs`, and in `syscall/misc.rs` `nanosleep`, `clock_nanosleep`, `sleep_rest`, `sleep_until`, `getitimer`, `setitimer`, `check_itimer`, `read_itimerval`, `itimer_value`, `write_itimerval`, `clock_gettime`, `clock_getres`, `cpu_clock` and `gettimeofday`; deadline bases and saturation, clock jumps, interval and POSIX timers, CPU-time-limit expiry, load averages and the timer thread's periodic work. CPU accounting, resource-limit syscalls, generic waits and the fast path remain kernel/process's; time-namespace offsets remain kernel/ns's; clock setting, timezone and restart dispatch remain kernel/signal's; timerfd remains kernel/poll's.
- `kernel/boot` — machine lifecycle and virtual init: `core/kernel/src/inittab.rs`, the `INIT` constant in `kernel.rs`, `reboot` in `syscall/misc.rs`, and in `machine.rs` `MachineOptions`, `Stdio`, the `Machine` owner, `SHUTDOWN_TIMEOUT`, `Machine::start`/`start_kernel`, `boot`, `spawn`/`spawn_process`, `shutdown`, `inittab`, `run_init_process`, `kill_all`, `take_power`, `Drop for Machine` and `run`; kernel startup, host-launched programs, PID 1's boot and power policy, inittab and shutdown. Shared kernel fields, general reparenting/reaping, host wait helpers, process statistics and the remaining Machine methods stay with kernel/process; timer work stays with kernel/time, bug containment and watchdog with kernel/bug, signal syscall call sites with kernel/signal and console behaviour with kernel/tty.
- `kernel/bug` — bug containment, kill reports and the BKL watchdog: `core/kernel/src/bug.rs`, `watchdog.rs`, `Hold`/`HoldSample`/`Entry`/`Doing`/`doing`/`done` in `kernel.rs`, `Machine::take_kills` and `Machine::stall` in `machine.rs`, and the `TEST_SYSCALL` (`0xa991`) dispatch arm in `syscall/mod.rs`; panic containment and `host_call`, kill report queuing, lock-free BKL holder sampling and stall reporting, FIFO end-of-hold kernel logging and debug/`test-hooks` fault injection. BKL acquisition/release, task/group exit and syscall dispatch remain kernel/process's; watchdog start/stop remains kernel/boot's; OOM victim selection remains kernel/oom's.
- `kernel/exec` — program execution: `core/kernel/src/loader.rs` and the execve section of `syscall/proc.rs`; execve and execveat (the argument limit, targets, `#!` scripts, `ETXTBSY`, the effects of set-id bits and file capabilities), the ELF loader (checks, doomed images, segment mapping, placement, the initial stack and auxv), the point of no return, the process's `exe_file`, the executable cache and the names of the program's mappings.
- `kernel/ns` — namespaces: `core/kernel/src/nsproxy.rs`, `pidns.rs`, `syscall/ns.rs`, the unshare section of `syscall/proc.rs`, the time-namespace offsets in `syscall/misc.rs` and user namespaces in `cred.rs`; creating namespaces at clone and unshare, setns and the namespace-file ioctls, user namespaces' ID maps and the translation of IDs shown outward, pid namespaces' tables, time-namespace offsets and their vDSO stubs, UTS and cgroup namespaces, namespace counts and limits, and nsfs files.
- `kernel/futex` — futexes: `core/kernel/src/futex.rs`, the futex and robust-list handlers in `syscall/misc.rs` and the futex call of `syscall/fast.rs`; keys, the waiter queue the BKL and fast paths share, the futex commands with `FUTEX_WAKE_OP` and `futex_waitv`, PI locks and their hand-over when an owner exits, robust lists and `clear_child_tid` wakes.
- `kernel/signal` — signals and the user-visible ABI: `core/kernel/src/signal.rs`, `syscall/sig.rs`, `coredump.rs`, `klog.rs`, `stub.rs`, `errno.rs`, `debug.rs`, signalfd in `fd.rs`/`syscall/sig.rs`, the restart and unimplemented-syscall handling in `syscall/mod.rs`, the fault-to-signal branch in `task.rs`, and uname/syslog/adjtimex/clock setting/restart_syscall in `syscall/misc.rs`; delivery, frames and sigreturn, restart, faults, core dumps, kernel logging, the Linux 6.1 ABI and ENOSYS policy, stub counts and host debug tracing. Ptrace implementation is kernel/ptrace and vDSO image construction is kernel/vdso; signal-side calls into both remain here.
- `kernel/ptrace` — guest tracing: `core/kernel/src/ptrace.rs` and `syscall/ptrace.rs`; tracer requests and tracee stops, saved registers, hardware debug slots, traced exits and process_vm_readv/writev. Signal/task/dispatcher/clone/exec/wait/seccomp call sites remain in their existing modules; procfs memory-file handling stays kernel/procfs's, access policy kernel/cred's and memory writes kernel/mm's.
- `kernel/vdso` — guest vDSO images: `core/kernel/src/vdso.rs`; host-image discovery/validation, fallback ELF, signal-return trampoline and clock-stub detection. Image mapping and auxv stay kernel/exec/kernel/mm's, time-namespace switching kernel/ns's, clock syscalls kernel/time's and fast dispatch kernel/process's.
- `kernel/store` — the rootfs inode store: `core/kernel/src/vfs/store.rs`, `vfs/import.rs`, `vfs/browse.rs` and the host wrappers in `lib.rs` (`import_rootfs`, `sync_store`, `browse`, `browse_changing`, `write_file`, `read_file`); SQLite namespace and objects, deferred commits and power-loss ordering, the reaper and checkpoints, boot cleanup, the metadata cache, sharing with the DocumentsProvider, rootfs import, the host browse API.
- `kernel/vfs` — the VFS layer: `core/kernel/src/vfs/mod.rs` (except the mount table and the overlay methods), `vfs/dev.rs`, `syscall/fs.rs` (except kernel/files' and kernel/fileio's parts, its overlay functions, `flock`, the fcntl lock commands and the pipe, FIFO and splice code: `getdents64`, the sections Metadata, stat, Changing the namespace, chmod, chown and utimensat, Paths and tmpfs accounting, and the remaining shared helpers), and in `syscall/mount.rs` the tmpfs options; mount-aware nodes and path resolution (openat2 `RESOLVE_*`, the no-BKL `Cached` resolver), mount-flag checks in file operations, tmpfs instances, metadata and namespace syscalls, `/dev` population and device numbers, and the calls into the overlay and inotify code.
- `kernel/files` — open files: the render-node interfaces in `core/kernel/src/gpu.rs` and `syscall/gpu.rs`, `core/kernel/src/fd.rs` (its `EventFd` and `TimerFd` are kernel/poll's), and in `syscall/fs.rs` the section Opening, closing, duplicating (except `write_at`, `clone_range` and the `FICLONE`/`FICLONERANGE`/`FIDEDUPERANGE` ioctl arms in kernel/fileio, `open_overlay`, `flock`, the fcntl lock commands, `pipe2`, `open_fifo` and the pipe-size fcntl commands) and the shared helpers `executing` and `open_for_write`; fd tables and open file descriptions, fcntl and ioctl dispatch, opening paths (magic-link reopens, file handles, memfd, character devices by number, random and render-node ioctls).
- `kernel/fileio` — file data I/O, size changes, syncing and object sharing: in `core/kernel/src/syscall/fs.rs`, `write_at`, `clone_range` and the `FICLONE`/`FICLONERANGE`/`FIDEDUPERANGE` ioctl arms, the section Reading and writing (except `follow_copy_up`, `copy_up`, the pipe reads and writes and the splice block), `lseek`, the sections Cache hints and syncing and truncate and fallocate, and the shared helpers `check_seals`, `seals_permit`, `remove_privs` and `truncating`; per-kind read/write and vectored paths, regular-file unlocked I/O with `f_pos_lock` emulation, sendfile and copy_file_range, clones and object unsharing (`prepare_write`, `make_private`, `rehome`), truncate/ftruncate/fallocate, cache hints and syncing.
- `kernel/overlay` — overlayfs: `core/kernel/src/vfs/overlay.rs`, the overlay methods of `Vfs` in `vfs/mod.rs`, `open_overlay`, `follow_copy_up`, `copy_up`, `unlink_overlay`, `link_overlay` and `rename_overlay` in `syscall/fs.rs`, and in `syscall/mount.rs` the overlay options and the overlay node sweep; mounting and layers, lookup through layers with whiteouts and opaque directories, node lifetime and the sweep, merged readdir and stat, copy-up, creating, removing and renaming through an overlay, and files opened through one.
- `kernel/locks` — advisory locks and leases: `core/kernel/src/locks.rs`, `syscall/lease.rs`, and `flock` and the fcntl lock commands in `syscall/fs.rs`; flock, POSIX and OFD locks with ranges, waits and deadlock detection, leases and their breaks, and the `/proc/locks` and fdinfo listings.
- `kernel/pipe` — pipes and splicing: `core/kernel/src/pipe.rs`, and in `syscall/fs.rs` `pipe2`, `open_fifo`, the pipe-size fcntl commands, pipe reads and writes and the splice block (`splice` to `wait_splice_done`); pipe buffers and capacity, FIFO opens, `SIGPIPE`, and splice, tee and vmsplice with their checks and waits.
- `kernel/xattr` — extended attributes: `core/kernel/src/syscall/xattr.rs`, `vfs/acl.rs`; the xattr syscalls, name prefixes and permissions, POSIX ACL encoding, access checks and default inheritance, and `security.capability`'s checks and conversions.
- `kernel/mount` — mounts and mount namespaces: `core/kernel/src/syscall/mount.rs` (except the tmpfs and overlay options and the overlay node sweep) and the mount table in `vfs/mod.rs` (`Mount`, `Mounts`, `MntNs`, `Propagation`, `Index`, `GroupAlloc` and the `Vfs` methods that add, copy, move, propagate, unmount and collect mounts and namespaces); boot mounts, mount(2) with binds, remounts and moves, umount2, pivot_root, open_tree/move_mount/mount_setattr, superblock flags, propagation between peers and slaves, mount locks, `fs.mount-max`, copying, entering and collecting mount namespaces, and the mount data mountinfo shows.
- `kernel/inotify` — inotify: `core/kernel/src/syscall/inotify.rs`; instances, watches and their per-user limits, the per-kernel registry keyed by store inode or by overlay, FUSE or cgroup2 node key, the hooks at Linux's fsnotify call sites and the events they report, the `Opened` record of open files, and replaying the Files app's and cgroup2 files' changes as events.
- `kernel/aio` — native AIO: `core/kernel/src/syscall/aio.rs`; io_setup to io_pgetevents, contexts per thread group and their `aio-nr` charge, synchronous reads, writes and fsyncs at submission, pending `IOCB_CMD_POLL`s completed by io_getevents, io_cancel or the timer thread, and context release at execve and exit.
- `kernel/loop` — loop devices: `core/kernel/src/syscall/loopdev.rs`; `/dev/loop-control` and `/dev/loop<N>` (the only block devices), openers and exclusive claims, binding to a backing file, status, capacity and block-size requests, I/O forwarded to the backing file at the device offset, block ioctls, and the `/sys/block/loop<N>` values.
- `kernel/fuse` — FUSE: `core/kernel/src/vfs/fuse.rs`, `syscall/fuse.rs`; filesystems a guest daemon serves through `/dev/fuse` (Linux 6.1's `fs/fuse`): mount options and connections, INIT negotiation, requests and replies with interrupts and aborts, the device file (read, write, splice, poll, clone), the node cache path resolution reads and the syscall retry that fills it, and the file syscalls on FUSE nodes (open and create, I/O, directories, namespace and attribute changes, xattrs, flushes and releases, mapped page fills and writeback, copies for execve).
- `kernel/procfs` — synthetic filesystem core and non-sysctl/non-sysfs views: `core/kernel/src/pseudo.rs` except `kernel/sysctl`'s `/proc/sys` tables/variants/handlers and `kernel/sysfs`'s sysfs tables/variants/section; procfs (per-process and system-wide files, `/proc/sysvipc`, `/proc/<pid>/net`), devpts and nsfs nodes, the mqueue filesystem's nodes, the shared `Pseudo`/`View`/`FileKind::Proc` snapshot framework, and the cgroup2 node adapters for lookup, metadata, listing and dispatch to kernel/cgroup. Cgroup policy and device BPF belong to kernel/cgroup; `/proc/sys` belongs to kernel/sysctl; `/sys` belongs to kernel/sysfs.
- `kernel/sysctl` — `/proc/sys` sysctls: in `core/kernel/src/pseudo.rs`, the `sys/*` entries of `STATIC`, `RECORDED`, `recorded`, `recorded_value`, `NET_CONF4`, `NET_CONF6`, `PseudoNode::NetConf`, `PseudoNode::NetSysctl`, `PseudoNode::Static(b"sys/...")`, `sysctl_kind`, `is_net_sysctl`, and the `/proc/sys` arms of `View`, `stat`, `owner_of`, `readdir`, `writable`, `unwritable_error`, `open_unwritable`, `pollable`, `unreadable`, `content` and `write`; `proc_sys_permission`/`test_perm` open checks, namespace ownership and scoping, recorded sysctls (`Kernel::sysctls`) and write handlers. Shared `View`/snapshot plumbing remains kernel/procfs's; backing `netconf::SYSCTLS` and per-device conf stay kernel/netns's.
- `kernel/sysfs` — synthetic `/sys` filesystem: in `core/kernel/src/pseudo.rs`, `SYS_GPU`, `SYS_STATIC`, `SYS_NET_DIR`, `SYS_BLOCK_DIR`, `BLOCK_FILES`, `NET_FILES`, `BRIDGE_FILES`, `PORT_FILES`, `SYS_CPU_DIR`, `CPU_FILES`, `HOST_CPU_FILES`, `CGROUP_POINT`, `PseudoNode::{SysRoot, Sys, SysCpu, SysNet, SysBrif, SysBlock}`, the `sysfs` section (`net_file`, `cpu_file`, `cpu_list`, `cpu_mask`, `host_cpu_file`, `parse_cpu_list`, `parse_cpu_mask`, `cpu_list_of`, `cpu_mask_of`, `host_cpu_has`, `host_cpu`), and the sysfs arms of `View`, `stat`, `fs_of`, `readdir`, `node_ino`, `ino_of`, `open_unwritable`, `pollable` and `content`; CPU topology and host-copied `cache/`/`cpufreq/`, `/sys/class/net`, `/sys/block/loop<n>`, overlayfs module parameters, `/sys/fs/cgroup/` mount point and conditional platform DRM render-node paths. Shared `View`/snapshot plumbing remains kernel/procfs's and mounting kernel/mount's.
- `kernel/cgroup` — cgroup v2 and device BPF: `core/kernel/src/cgroup.rs`, `bpf.rs`, `syscall/bpf.rs`; the cgroup tree and interface files, membership and migration, controller delegation and enforced limits, freezing and killing, change observation for poll and inotify, and the bpf(2) subset for cgroup device programs (verification, attachment and execution). Synthetic node adapters remain kernel/procfs's; namespace creation, mount creation, file-syscall call sites, the freezer wait and OOM victim selection remain with kernel/ns, kernel/mount, kernel/files and kernel/vfs, kernel/signal and kernel/oom respectively.
- `kernel/tty` — terminals: `core/kernel/src/tty.rs`, `syscall/tty.rs`, `terminal.rs`; in-process PTY pairs (allocation, opening, hangup and vhangup), the line discipline and termios/termios2, packet mode, job control (controlling terminals, foreground groups, background checks, terminal signals), and the host console used by the app's tabs and the `appine-run` bridge.
- `kernel/net` — the socket layer for internet sockets and the socket syscalls every family goes through: `core/kernel/src/net.rs` (except its netlink sections), `syscall/net.rs` (except its `netlink_*` functions, its netlink section, the `Socket::Netlink` arms, and `kernel/rawicmp`'s `raw_recv` and `take_errors`), `portmap.rs`, `traffic.rs`, `origdst.rs`; TCP/UDP passthrough to host sockets with emulated blocking and options, the DNS stub, low-port mapping and the inbound forwarding hooks, traffic counters and the `/proc/net` socket and protocol files, `SO_ORIGINAL_DST`, `SO_MARK` and legacy route ioctls. Raw ICMP belongs to kernel/rawicmp, the routing table to kernel/route and netlink sockets to kernel/netlink.
- `kernel/rawicmp` — raw ICMP and ICMPv6 sockets emulated on host ping sockets: `core/kernel/src/rawicmp.rs`, and `raw_recv` and `take_errors` in `core/kernel/src/syscall/net.rs`; per-namespace epoll aggregation points (`Tap`), echo-id restoration, UDP TTL probe tapping and ICMP error reassembly, synthetic IPv4 headers and raw ICMP socket options. Socket-syscall dispatch and `InetSocket` fields remain kernel/net's; periodic tap polling remains kernel/time's.
- `kernel/route` — synthesized routing tables and FIB rules: `core/kernel/src/route.rs`; assembling main and local tables from Android `LinkProperties` (`Machine::set_routes`), host `/proc/net/route` or interface addresses merged with virtual-device routes, `ip route get`, `RTM_GETROUTE`/`RTM_GETRULE` message encoding and `/proc/net/route` and `ipv6_route`. `Machine::set_routes` storage remains in `machine.rs` (kernel/process), netlink transport in kernel/netlink and legacy route ioctls in kernel/net.
- `kernel/netlink` — netlink sockets in process: in `core/kernel/src/net.rs` the sections netlink, rtnetlink notifications, `NETLINK_GENERIC`, Netlink messages and `NETLINK_SOCK_DIAG`; in `syscall/net.rs` the `netlink_*` functions, the netlink section (`netlink_send`, `rtnl_watched`, `CHANGING_IOCTLS`, `rtnl_notify`, `KernelHost`) and the `Socket::Netlink` arms of the socket calls; binding, groups and options, request handling and reply queues, rtnetlink queries and change requests, link, address and route notifications, `nlctrl`, `NETLINK_SOCK_DIAG`, the `NETLINK_NETFILTER` entry point and `NETLINK_KOBJECT_UEVENT`.
- `kernel/netns` — network namespaces without a network stack: `core/kernel/src/netns.rs`, `netdev.rs`, `forward.rs`, `netconf.rs`; host loopback blocks and address translation, namespace ports/listeners, virtual devices with routes/sysctls, packet construction and hook routing into kernel/nft, and forwarding outside connections to published ports. The ruleset control plane and expression evaluator in nft.rs belong to kernel/nft; socket and netlink call sites remain kernel/net/kernel/netlink's.
- `kernel/nft` — nftables rulesets and evaluation: `core/kernel/src/nft.rs`; NETLINK_NETFILTER batches, tables/chains/rules/sets, query encoding and synthetic-packet expression execution. Namespace path construction, hook selection and forwarding stay kernel/netns's; socket verdict application and netlink transport stay kernel/net/kernel/netlink's.
- `kernel/unix` — AF_UNIX sockets emulated in process: `core/kernel/src/unix.rs`, `syscall/unix.rs`; stream, datagram and seqpacket sockets, path and abstract names, connection lifecycle, data transfer with `SCM_RIGHTS`/`SCM_CREDENTIALS`/`SO_PEERCRED`, readiness, `/proc/net/unix`, and the garbage collector for in-flight cycles.
- `kernel/poll` — I/O multiplexing: `core/kernel/src/syscall/poll.rs` and `syscall/timerfd.rs`; the shared readiness model (`readiness`, `arrivals`, `wake_objects`), ppoll and pselect6, epoll (edge triggering, nesting, ONESHOT, EXCLUSIVE gates), eventfd2, timerfd, and signal-driven I/O checked by the timer thread.
- `kernel/ipc` — System V IPC and POSIX message queues: `core/kernel/src/ipc.rs`, `syscall/ipc.rs`, `syscall/mqueue.rs`; per-IPC-namespace object tables and limits, SysV ids and `ipc_perm` checks, message queues, semaphores with `SEM_UNDO`, shared memory segments and their destruction, the `mq_*` syscalls and the message-queue objects (priority order, blocking, notification) behind the mqueue filesystem, and the contents of `/proc/sysvipc`.
- `kernel/cred` — credentials, capabilities and seccomp: `core/kernel/src/cred.rs` (except user namespaces), `syscall/cred.rs`, `seccomp.rs`; the credential structure and id syscalls, capability scopes, `capset` and the capability prctls, securebits, the execve credential transition with file capabilities, DAC and ownership helpers, signal and ptrace access checks, and guest seccomp (strict mode, cBPF filters, actions, TSYNC, user notifications, the always-allow cache).
- `kernel/mm` — guest memory: `core/kernel/src/mm.rs` (except what kernel/mmu, kernel/oom, kernel/cow and kernel/hostmem list there), `core/kernel/src/syscall/mem.rs` (except process_mrelease), `core/kernel/src/uaccess.rs` (`UserSlice`), and the page-fault branch of the task run loop; address spaces and VMAs, the memory syscalls, brk and stack growth, the fault policy, `[vvar]`/vDSO mapping, file mappings at EOF and truncation, FUSE mappings read on demand, and the maps and core-dump views.
- `kernel/cow` — fork and copy-on-write: in `core/kernel/src/mm.rs`, the `fork` section (`Mm::fork`, `commit_too_big`, `carve`, `spare_below`) and the `Copy-on-write` section (`MmRef`, `Loan`, `PageHasher`, `Loans`, `Runs`, `Borrowed`, `Cow`, and the CoW `impl Mm` methods except `shootdown`, which belongs to kernel/mmu); fork commit estimation, `anon_vma_fork` identities, per-VMA carving/cloning, page-granular lending, borrower materialization, owner recall/repossession, and CoW hooks for VMA mutations and teardown.
- `kernel/hostmem` — host backing and deferred release: in `core/kernel/src/mm.rs`, the `Host backing` section (`RESERVED_HOST`, `HostRegion`, `SharedMemory`, `FileMaps`, `FileMap`, `content_version`, `content`/`WRITABLY_SHARED`, `Carved`, `spare`, `Unmapped`/`UNMAPPED`/`UNMAPPING`, `defer_unmaps`, `release_unmapped`, `recycled`, `discard_host`, `discard_file_host`, `remove_host`, `copy_nonzero_pages`) plus `Mm::mmap_gpu`'s host-mapping retention contract; host memory ownership across anonymous, file, reserved, foreign and GPU VMAs, read-only file-mapping sharing, host commit accounting, 16 KB alignment, recycling and pre-mapped fork pools, and BKL-deferred unmapping.
- `kernel/mmu` — the soft-MMU: the page table in `core/engine/src/c/mmu.c`, the `Mmu` wrapper, and `core/engine/tests/mmu.rs`, the software TLB in `core/engine/src/c/cpu.c` and `internal.h`, and in `core/kernel/src/mm.rs` the `Consistency and code` section and the `Mm` methods that fill entries (`map_pages`, `fault_in`) and keep threads consistent (`add_user`, `remove_user`, `generations`, `code_space`, `invalidate_code`, `sync`, `quiesce`, `shootdown`); page-table entries and their population, the TLB and its Tier 0 refill, shootdowns and quiescing, the code-change log, and code groups sharing translations.
- `kernel/oom` — memory accounting and the OOM killer: `core/kernel/src/oom.rs`, the resident-memory measures (`resident_in`, `cow_shared`, `pagemap`, `stack_bytes`, `resident_pages`, `peak_resident_pages`, `resident_split`, `Usage`) and `Mm::release` in `mm.rs`, and process_mrelease in `syscall/mem.rs`; resident memory for procfs, rusage and child cgroups, the app-wide and cgroup limits, victim choice and kills, `oom_score`, process_mrelease, and the release of written code views.
- `hal` — the host abstraction layer: `core/hal/` (`lib.rs`, `net.rs`); one implementation for Android (bionic) and Linux (glibc) hosts returning raw host errnos: host memory mappings and residency, file and storage calls on the object directory, host statistics and CPUs, polling with `Event`/`Edges`/`Watch`, per-thread host controls and clocks, host sockets, interfaces, routes and DNS, and the CLI's terminal helpers.
- `android/service` — the app's foreground service: `android/app/src/main/java/io/github/mthli/appine/TerminalService.kt`, `BrowserBridge.kt`, `LanAddresses.kt`, `Settings.kt`, `Tabs.kt`; owning the kernel, browser endpoint and all sessions, start, boot, shutdown, reboot and distro replacement, the ongoing foreground notification and wake lock, memory trimming, the 2 s poll of kernel events, routing program requests and tab restore after the app was killed. Non-ongoing notifications, fault reports and diagnostic retention/export belong to android/reports.
- `android/reports` — notifications, fault reports and diagnostics: `android/app/src/main/java/io/github/mthli/appine/Notifications.kt`, `Diagnostics.kt`; notification channels and locale renaming, kill/bug/crash/stall/boot-failure/listen/tab notifications, copyable English fault reports and `ReportReceiver`, bounded logcat and report retention (`DiagnosticFiles`) and serialized ZIP export (`DiagnosticProvider`). The ongoing foreground notification and event-routing decisions remain android/service's; authenticated private notification clipboard UI remains android/privacy's; export UI and SAF save picker remain android/settings's.
